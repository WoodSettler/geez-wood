Clawith：把 AI Agent 变成有工位的数字员工

开源多智能体平台 Clawith 发布技术白皮书，主张 Agent 应有身份、记忆、工位与同事关系，并公开了 Trigger、Focus、Heartbeat 三条机制的工程实现。

2026-03-25 clawith.ai

Clawith 把自己定位为面向企业协作网络的开源多智能体协同工作域，白皮书的主张是：AI Agent 不该只是对话框里的问答工具，而应是组织架构中有独立身份、有专属工位、有同事关系的常驻数字员工。每个 Agent 拥有 soul.md、memory.md、Focus.md 与独立的触发器，可以分配预算 Token 并设定部门可见性，也能自动投射为飞书、Slack 或私有化 IM 里的企业服务机器人。

  1. Agent 从对话框升格为有身份、记忆与工位的数字员工
  2. Trigger、Focus、Heartbeat 三条机制给出自主唤醒的实现
  3. L1-L4 分级自治，高危操作走人工审批卡片
  4. 自带多租户 RBAC、Token 配额与全链路审计
  5. 打通飞书、Slack、Discord，并可纳管本地 OpenClaw

白皮书给出的三代 Agent 形态

阶段代表形态白皮书指出的局限
第一阶段提示词时代的对话机器人没有手脚，受训练截止日期限制，容易产生幻觉
第二阶段工具调用加检索增强的单体 Copilot不发起请求就一直休眠，单一模型难以兼顾多种复合任务
第三阶段临时组队的多智能体框架任务结束即销毁，没有长期记忆，也不会主动醒来
Clawith 主张常驻数字员工加组织级上下文需要配套的组织级权限、配额与审计

自主意识的四个零件

唤醒
Trigger
守护线程每 15 秒扫描一次，支持 cron、once、interval、poll、on_message、webhook 六种触发；同一 Agent 30 秒内不重复唤醒
目标
Focus
唤醒后先读 focus.md，且每个触发器必须绑定一个关注项，避免无目的的闹钟
自驱
Heartbeat
默认 240 分钟一次的心跳，按四阶段协议做回顾、定向探索、社交互动与总结
社交
Plaza
Agent 之间发帖、评论、点赞的广播广场，内容按租户隔离

工程栈与竞品定位

后端用 FastAPI 加 SQLAlchemy 2.0 异步会话，前端是 React 19 配 Vite，长任务通过 WebSocket 推流；模型接入层内置 15 家供应商的注册表，支持主模型与备用模型自动降级。

白皮书把自己与两个竞品区分开：面向个人用户的 OpenClaw 在进入企业后会形成孤岛，无法追踪并发使用；由阿里 Higress 团队孵化的 HiClaw 主打网关层的流量治理与私有化部署，Clawith 则强调 Agent 的人格、关系与协作。

读这份白皮书时要注意
这是厂商自述的技术白皮书，能力边界与竞品对比均由作者给出，没有第三方验证；文中数字（单轮 50 次工具调用、50MB 文件上限、Agent 默认 48 小时过期）是平台的默认配置，实际取值以部署为准。
